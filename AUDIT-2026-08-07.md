## Executive Summary

- **Audit Health Score: 14/20 (Good)**
- **Total issues found: 15** (P0: 0, P1: 3, P2: 7, P3: 5)
- **Top 3 critical issues:**
  1. **No keyboard focus indicators anywhere** — `:focus-visible` is absent from every component. Keyboard-only users cannot see where they are on the page.
  2. **No `<main>` landmark** — every page wraps content in `<div>` or `<motion.div>` without a `<main>` element. Screen reader users cannot jump to content.
  3. **`<html lang="en">` hardcoded** — the `lang` attribute does not update when the user switches to Chinese, breaking screen reader pronunciation.
- **Recommended next step:** `/impeccable adapt` to fix focus indicators, landmarks, and semantic HTML issues.

## Detailed Findings by Severity

### P1 — Major

#### [P1] No keyboard focus indicators anywhere
- **Location:** Global — `app/app.css` (entire file)
- **Category:** Accessibility
- **Impact:** Keyboard-only users (including many power users, motor disability users, and screen reader users) cannot see which element is focused. This makes the site effectively unnavigable by keyboard.
- **WCAG:** 2.4.7 Focus Visible (Level AA)
- **Recommendation:** Add `:focus-visible` outline styles to all interactive elements. Use `2px solid rgba(255, 255, 255, 0.55)` on dark backgrounds and `2px solid rgba(0, 0, 0, 0.4)` on cream cards, with `outline-offset: 2px`.
- **Suggested command:** `/impeccable adapt`

#### [P1] No `<main>` landmark on any page
- **Location:** `app/routes/home.tsx:27`, `app/components/pseo-layout.tsx:24`, `app/components/home-view.tsx:233`
- **Category:** Accessibility
- **Impact:** All primary views wrap content in `<div>` or `<motion.div>` with no `<main>` element. Screen reader users navigating by landmark cannot jump directly to content. The only `<main>` is inside the ErrorBoundary (`root.tsx:72`).
- **WCAG:** 1.3.1 Info and Relationships (Level A)
- **Recommendation:** Wrap `<Outlet />` in `<main>` in `root.tsx`, and replace the outermost `<div>`/`<motion.div>` in home-view and pseo-layout with `<main>`.
- **Suggested command:** `/impeccable adapt`

#### [P1] Hardcoded `lang="en"` on `<html>` with Chinese UI
- **Location:** `app/root.tsx:31`
- **Category:** Accessibility
- **Impact:** When the user switches to Chinese, the `lang` attribute remains `"en"`. Screen readers apply English pronunciation rules to Chinese text, making it unintelligible.
- **WCAG:** 3.1.1 Language of Page (Level A)
- **Recommendation:** Set `lang` dynamically from the language context. Use `zh-Hans` for Simplified Chinese, `en` for English.
- **Suggested command:** `/impeccable adapt`

### P2 — Minor

#### [P2] Comparison table uses divs, not semantic `<table>`
- **Location:** `app/components/comparison-table.tsx:30-49`
- **Category:** Accessibility
- **Impact:** Screen readers cannot navigate the comparison data as a table. The `div`-based grid with CSS grid has no row/column relationships. The `comparison-metric-label` spans are hidden with `display: none` at desktop sizes, which also hides them from screen readers — meaning users hear checkmark values without knowing which column they belong to.
- **WCAG:** 1.3.1 Info and Relationships (Level A)
- **Recommendation:** Use `<table>`, `<thead>`, `<tr>`, `<th>`, `<td>` elements. Alternatively, add `role="table"`, `role="row"`, `role="columnheader"`, `role="cell"` to the existing divs, and ensure column labels are available to screen readers at all sizes.
- **Suggested command:** `/impeccable adapt`

#### [P2] No skip-to-content link
- **Location:** `app/root.tsx:29-44`
- **Category:** Accessibility
- **Impact:** Keyboard and screen reader users must tab through the entire sticky nav bar (GitHub link, language switch) on every page before reaching content.
- **WCAG:** 2.4.1 Bypass Blocks (Level A)
- **Recommendation:** Add a visually hidden skip link at the top of `Layout` that jumps to `#main-content`.
- **Suggested command:** `/impeccable adapt`

#### [P2] Explore section uses `<p>` as a heading
- **Location:** `app/components/home-view.tsx:445`
- **Category:** Accessibility
- **Impact:** The explore section title is a `<p>` instead of a heading (`<h2>` or `<h3>`). The heading outline is: `<h1>` (home-title) → `<h2>` (graph-pitch-title) → `<h2>` (pricing-compare-title) → `<p>` (explore-title). Screen reader users navigating by heading will miss the explore section entirely.
- **WCAG:** 1.3.1 Info and Relationships, 2.4.6 Headings and Labels (Level AA)
- **Recommendation:** Change `<p className="explore-title">` to `<h2 className="explore-title">` or `<h3>`.
- **Suggested command:** `/impeccable adapt`

#### [P2] PricingCompare uses `<div>` not `<section>`
- **Location:** `app/components/home-view.tsx:133`
- **Category:** Accessibility
- **Impact:** `PricingCompare` wraps in `<div>` while `GraphPitch` (line 172) correctly uses `<section>`. Both contain an `<h2>` heading. Screen readers navigating by landmark will not discover pricing as a distinct region.
- **WCAG:** 1.3.1 Info and Relationships (Level A)
- **Recommendation:** Wrap the PricingCompare section in `<section>`.
- **Suggested command:** `/impeccable adapt`

#### [P2] Decorative barcode lacks `aria-hidden`
- **Location:** `app/components/barcode.tsx:18-27`
- **Category:** Accessibility
- **Impact:** The barcode bars are purely decorative `<div>` elements with no semantic meaning. The divider has `aria-hidden="true"` but the barcode container does not.
- **WCAG:** 1.1.1 Non-text Content (Level A)
- **Recommendation:** Add `aria-hidden="true"` to the barcode container `<div>`.
- **Suggested command:** `/impeccable adapt`

#### [P2] Copy button lacks descriptive `aria-label`
- **Location:** `app/components/code-block.tsx:39-47`
- **Category:** Accessibility
- **Impact:** The copy button reads "Copy" / "Copied" but does not say what is being copied. Screen reader users hear "Copy" without context.
- **WCAG:** 2.4.6 Headings and Labels (Level AA)
- **Recommendation:** Add `aria-label` to the copy button, e.g. `aria-label={t.copyLabel ?? "Copy install command"}`.
- **Suggested command:** `/impeccable clarify`

#### [P2] Detector: font sizes outside DESIGN.md type ramp
- **Location:** `app/app.css:216, 400`
- **Category:** Implementation Integrity
- **Impact:** Two fluid sizes use endpoints (1.15rem, 1.25rem) not on the DESIGN.md type ramp. Minor inconsistency for AI consumers.
- **Recommendation:** Update DESIGN.md to document these as additional size steps, or adjust to map to documented sizes.
- **Suggested command:** `/impeccable document`

### P3 — Polish

#### [P3] `will-change: transform` always-on on animated elements
- **Location:** `app/app.css:371, 803, 820, 859, 1063, 1440`
- **Category:** Performance
- **Impact:** `will-change` is always-on at rest on 6 elements. Spec recommends applying only during animation. Impact is minimal given only 6 instances.
- **Recommendation:** Apply `will-change` via JavaScript only during hover, or keep as-is since elements are known to animate.
- **Suggested command:** `/impeccable optimize`

#### [P3] `white-space: nowrap` on card titles could overflow
- **Location:** `app/app.css:419`
- **Category:** Responsive Design
- **Impact:** Entry card titles have `white-space: nowrap` above 681px. If a title line is unusually long, it could overflow. Current content fits.
- **Recommendation:** Add `overflow: hidden; text-overflow: ellipsis` as safety net, or remove `nowrap`.
- **Suggested command:** `/impeccable adapt`

#### [P3] Error boundary uses Tailwind utilities inconsistent with design system
- **Location:** `app/root.tsx:72`
- **Category:** Implementation Integrity
- **Impact:** Error boundary uses `pt-16 p-4 container mx-auto` — Tailwind utilities not used elsewhere in the project. Inconsistent with the custom CSS approach.
- **Recommendation:** Style the error boundary using the same CSS custom properties (cream card on dark background, mono text).
- **Suggested command:** `/impeccable harden`

#### [P3] No `prefers-contrast` media query
- **Location:** `app/app.css`
- **Category:** Accessibility
- **Impact:** The site does not respond to `prefers-contrast: more`. Users who need higher contrast cannot adjust.
- **WCAG:** 1.4.3 Contrast (Enhanced) — advisory
- **Recommendation:** Add `prefers-contrast: more` override that increases `--ink-2` opacity from 0.55 to 0.75, and `--ink-3` from 0.35 to 0.55.
- **Suggested command:** `/impeccable adapt`

#### [P3] Detector: 1px radius on pricing bars
- **Location:** `app/app.css:286, 294`
- **Category:** Implementation Integrity
- **Impact:** Pricing comparison bars use `border-radius: 1px`, not in DESIGN.md's rounded scale.
- **Recommendation:** Add to DESIGN.md or change to 3px to match the system.
- **Suggested command:** `/impeccable document`

## Patterns & Systemic Issues

1. **No focus management system** — The complete absence of `:focus-visible` styles across all components indicates a systemic gap, not a one-off omission. Every interactive component is affected.
2. **Semantic HTML gaps** — No `<main>` landmark, comparison table uses divs, explore heading uses `<p>`. These are recurring but isolated gaps in HTML semantics.
3. **Token drift in DESIGN.md** — 5 instances where CSS uses values outside DESIGN.md's documented scale. Low-severity but indicates DESIGN.md was written from observation rather than being the source of truth.

## Positive Findings

- **Motion sensitivity is excellent.** `prefers-reduced-motion` is respected throughout — `useAccessibleMotion()` hook disables all animations consistently. CSS `animation: none` on decorative patterns when reduced motion is preferred.
- **Touch targets meet 44px.** All interactive buttons have `min-height: 44px` and `min-width: 44px`, meeting WCAG target size recommendations.
- **ARIA is used correctly on decorative elements.** SVG icons use `aria-hidden="true"`, the language switch has dynamic `aria-label`, and the copy button uses `aria-live="polite"`.
- **Entry cards are semantic `<button>` elements.** They are inherently keyboard accessible (can be focused and activated with Enter/Space). The only gap is the missing focus indicator.
- **Responsive design is thorough.** 8 breakpoints handle everything from 400px to 1100px, grids collapse smoothly, safe areas respected for notched devices.
- **Semantic navigation landmarks.** `<nav>` is used in sticky nav bars and footers.
- **Semantic HTML for lists.** Feature lists use `<ul>` and `<li>`.
- **Correct `type="button"` on all buttons.** Prevents accidental form submission.
- **No heavy images.** The entire site uses inline SVGs, CSS, and text — no `<img>` elements, no network requests for visuals.
- **Security best practices.** All external links use `rel="noopener noreferrer"`.
